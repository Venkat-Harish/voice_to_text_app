# ui: Compose screens for the in-app side of Voice (Talk, Models, History, Settings)

## Purpose
Everything drawn inside [../MainActivity.kt](../MainActivity.kt): the four tab screens, the Talk tab's own recorder (`InAppDictation`), shared widgets, the Material3 theme, and `SystemLinks`. Port of the prototype's `src/pages/*.jsx` + `src/styles/theme.css`. The floating bubble is not here: it is plain Android Views in [../dictation/](../dictation/CLAUDE.md).

## How it works
**Host.** `MainActivity` wraps everything in `VoiceTheme(settings.theme)`; `VoiceAppUi` switches tabs with a plain `when (tab)`: no Navigation library, no ViewModels. `modelsKind` is hoisted there (`rememberSaveable`) so Settings can open Models on SPEECH or VOICE; Talk's `goModels` always opens SPEECH. The Models tab gets a turmeric badge while any model is `DOWNLOADING`. Intent extra `tab=models` (`MainActivity.EXTRA_TAB`, singleTask, also in `onNewIntent`) jumps to Models.

**State in.** Screens read the [../VoiceApp.kt](../VoiceApp.kt) singletons directly with `collectAsStateWithLifecycle()`:
- `settings.flow` ([../data/SettingsRepository.kt](../data/SettingsRepository.kt)): all screens. `models.states` / `models.storage` ([../asr/ModelDownloads.kt](../asr/ModelDownloads.kt)): Home, Models, Settings, tab badge.
- `asr.state` (`AsrState`: status, stage, modelId, speed, error): Home, Models. `asr.errors` (SharedFlow) → toast in `HomeScreen`.
- `readAloud.state` / `readAloud.messages` ([../tts/ReadAloud.kt](../tts/ReadAloud.kt)): Home, Models. `transcript.paragraphs/partial`: Home only. `history.items`: History only.
- `DictationService.isRunning` / `bubbleStatus` (companion StateFlows): Home setup check, `BubbleStatusLine`. `InAppDictation.status/source/level`: Home, Models (busy guard).

**Calls out.** `SettingsRepository.setX` (fire-and-forget DataStore edits); `VoiceApp.selectModel(id)` (persist + load) for speech, `settings.setTtsModelId` for voices; `models.download/cancel/delete/deleteAll/refresh`; `readAloud.speak/stop/hearVoice/unload`; `transcript.clear`; `history.prune/delete/clear/countRemovedBy`; `VoiceApp.wakeSpeechModel()/loadSelected()`. Settings reach the live bubble with no UI plumbing: `DictationService` collects `settings.flow` and re-applies size, `GlassStyle`, idle opacity, speaker button, haptics and dock.

**Talk tab.** `SetupState` (mic, service enabled, notifications, battery) is re-read on every resume (`LifecycleResumeEffect`) and after each permission-launcher result. `setupDone = mic && (service enabled || DictationService running)`; only these two gate the layout, the other steps are optional. Steps: mic (`RequestPermission`); bubble service → `openAccessibility` (`android.settings.ACCESSIBILITY_DETAILS_SETTINGS` for `DictationService`, fallback `ACTION_ACCESSIBILITY_SETTINGS`), with a "greyed out?" hint → `openAppInfo` (`ACTION_APPLICATION_DETAILS_SETTINGS`, Android 13+ "Allow restricted settings"); notifications (API 33+ only); speech model → Models; battery → `ACTION_REQUEST_IGNORE_BATTERY_OPTIMIZATIONS`, fallback `ACTION_IGNORE_BATTERY_OPTIMIZATION_SETTINGS`. Once set up: `TryBubbleField` (an in-app field to try the real bubble on), a Notice if no on-device model is downloaded, then `TranscribePanel`: transcript card (partial in ink3 until `stable`), status line (shows `N.N× speed`; a Notice when speed < 1.0), dock = Copy / Share / `MicButton` / Read aloud (`readAloud.speak(transcript)`, stop while reading) / Clear (confirm). "or try the sample recording" shows for on-device models only. `TranscribePanel` calls `wakeSpeechModel()` on resume, and the mic reloads a model freed by idle-unload.

**InAppDictation vs the bubble.** Both are `DictationListener` clients of [../asr/Dictation.kt](../asr/Dictation.kt): `SystemDictation` when the selected model is `EngineKind.SYSTEM` (or unknown), else `OnnxDictation(app.asr)`. In-app text goes to `TranscriptStore` (paragraphs persisted to `transcript.json`, partial transient) and never to History. Bubble text (`dictation/DictationController`) is typed into another app and appended to History (password fields skipped). Both share the single `AsrHost`, so only one on-device session runs at a time. `start()` stops read-aloud first. `transcribeSample` feeds `assets/samples/jfk.wav` in `AudioCapture.BLOCK` chunks from its own `sample` thread straight into `AsrHost`; it needs a loaded on-device model. `onFinished` commits any leftover partial (Android's recognizer often ends on one).

**Models tab.** `LaunchedEffect` → `models.refresh()`. Card action by state: selected && READY → "In use"/"Loading…"; built-in (`!needsDownload`) → "Use"/"Unavailable" (`SpeechRecognizer.isRecognitionAvailable`/on-device, or any `TTS_SERVICE`); DOWNLOADING → "Pause" (`models.cancel`, `.part` files kept) + progress bar; READY → "Use"; PARTIAL → "Resume"; else "Download" (disabled while CHECKING). Tapping the card expands it: vendor/params, tags ("Recommended" = `VoiceApp.recommendedModelId` (by RAM) for speech, `model.recommended` for voices; live vs near-live; languages), blurb, "Hear this voice", "Delete from phone", license + model-card link. Footer: storage used/free.

**History tab.** `history.prune()` on entry. Row = text (6 lines max) + relative time + "typed/pasted/copied into <app label>". Empty state differs when history is off (`HISTORY_NEVER`).

**Settings tab.** Sections in order: Appearance (Light/Dark/System), Speech (model → Models SPEECH; language dialog from `ModelCatalog.LANGUAGES`), Read aloud (voice model → Models VOICE; voice dialog if the model has voices, else `openTtsSettings` = `com.android.settings.TTS_SETTINGS`, fallback `ACTION_SETTINGS`; speed `TTS_SPEEDS` 0.8/1/1.2/1.5×; Hear this voice), Memory (unload toggle; "Unload after" 5 s–60 min, chips 10 s/30 s/1 min/5 min), Bubble (Show toggle + `BubbleStatusLine`, `BubbleLookEditor`, only while typing, hide in full screen, speaker button in bubble, vibrate, reset position), Text (smart spacing, remove fillers, "Type it"/"Paste it" = `InsertMethod.AUTO/PASTE`), History (Forever/1/7/30/90 days, custom 1–3650, Don't save), App (Accessibility settings, App info, Delete all models), About.

**Bubble look.** `BubblePreview` hosts the real `dictation/BubbleView` (twice: in use at alpha 1, idle at the idle-fade alpha) and `EdgeTabView` (alpha `max(idle, GlassStyle.TAB_MIN_FILL)`) through `AndroidView`, styled with `GlassStyle(settings.bubbleColor, glass)`. The preview is drawn by the same `GlassPainter` code as the bubble, over a fixed light-to-dark gradient. Sliders: Size `BUBBLE_SIZE_MIN..MAX` = 32–64 dp in 2 dp steps; Glass opacity `GlassStyle.MIN_OPACITY`(0.3)–1 in 5 % steps; Idle fade 0.2–1 in 5 % steps (≥ 0.995 shows "Never fades"). Drags move local state only; the value is saved on `onValueChangeFinished`. Swatches = `BubblePalette.SWATCHES` (12, matched by RGB via `nameOf`), and the check-mark colour comes from `GlassStyle.prefersDarkMarks`. "Custom" opens `ColorPickerDialog` (HSV via `android.graphics.Color`); "Use colour" saves `parseHex(hex)`.

## Invariants & gotchas
- Use `Voice.colors` tokens only. Deliberate exceptions: fixed ink `0xFF1E1A16` on turmeric (`onPrimary`, `MicButton`), white on chilli, and the theme-independent preview/picker gradients. Outside `VoiceTheme`, `LocalVoiceColors` silently defaults to Light.
- Pre-Compose window colour: `res/values/colors.xml` paper `#F5EFE4` and `res/values-night/colors.xml` `#16130F` mirror `Light.paper`/`Dark.paper`. Change them together with Theme.kt. `values-night` follows the system, not the in-app theme.
- The app is edge-to-edge: `MainActivity` calls `enableEdgeToEdge()` and puts `imePadding()` on the root, and `TopBar` adds `statusBarsPadding()`. A screen without `TopBar` draws under the status bar.
- Tabs are `when`-switched, so a tab's composition is disposed when you leave it. Plain `remember` state is lost, and `LaunchedEffect(Unit)` runs again on every visit (Models refresh, History prune, toast collectors). SettingsScreen's `rememberCoroutineScope` is cancelled on tab change, and "Delete all models" runs `models.deleteAll()` in it.
- `asr.errors` and `readAloud.messages` are SharedFlows with no replay, so their toasts only appear while the Talk tab is composed. The bubble collects `readAloud.messages` separately.
- `InAppDictation` has no lifecycle hook: recording keeps going across tab switches and backgrounding until `stop()`. `start`/`transcribeSample` must stay no-ops unless IDLE, and its StateFlows are written on the main thread (the `DictationListener` contract).
- Before `models.delete(id)`, move the selection off the model (`selectModel(SYSTEM_ID)` / `setTtsModelId(SYSTEM_TTS_ID)`) and `readAloud.unload()` it if loaded. `ModelCard` and "Delete all" both do this; skip it and settings point at a missing model while an engine still holds its files.
- Select speech models through `VoiceApp.selectModel` (it loads the model). Select voices through `settings.setTtsModelId`, which also clears `ttsVoice` because voice ids differ per model.
- ModelsScreen's `busy` only knows about `InAppDictation` (speech) and `tts.reading` (voice), not a running bubble session.
- The built-in "Use" relies on the manifest `<queries>` for `RecognitionService` and `TTS_SERVICE`: remove them and it shows "Unavailable". The check is `remember`ed once per card.
- Settings writes are async (`edit` launched on `VoiceApp.scope`), so `app.settings.value` read right after a setter is still the old value. Render from the flow.
- Slider ranges/steps must match SettingsRepository's coercion and `onFivePercentGrid` snapping on read, or the thumb jumps after release.
- `SegmentedChoice` matches with `==`, so a stored `ttsSpeed` that is not exactly a `TTS_SPEEDS` value highlights nothing.
- `BubblePreview`'s tucked alpha duplicates `BubbleController`'s fade rule (`maxOf(idleOpacity, TAB_MIN_FILL)`); keep them in sync. Preview Views are `IMPORTANT_FOR_ACCESSIBILITY_NO` under `clearAndSetSemantics`, so TalkBack never reads the bubble's own labels.
- Changing History retention: VoiceApp prunes as soon as `historyDays` changes, so SettingsScreen calls `history.countRemovedBy(days)` first and confirms before `setHistoryDays`.
- `ConfirmDialog` calls `onConfirm()` then `onDismiss()`; callers reset their flag in `onDismiss`.
- `SystemLinks.copy` toasts only below API 33 (the system shows its own clipboard UI). History `appLabel`: own package → "Voice"; an unresolvable package → its last segment, capitalised.
- UI strings are hard-coded English in Kotlin; `strings.xml` holds only the app/service/channel names.
- `EXTRA_TAB=models` is handled, but nothing in the repo sends it today (the download notification has no content intent).

## How to extend
- **Setting row:** add the field, default, key `K.x`, `read()` line and `setX` in [../data/SettingsRepository.kt](../data/SettingsRepository.kt). Add a `Toggle`/`Item`/`SegmentedChoice` to the right `Section` in [settings/SettingsScreen.kt](settings/SettingsScreen.kt). Then consume it: bubble look → `DictationService.applyBubbleSettings`, bubble show/hide → `DictationService.updateVisibility` (see [../dictation/CLAUDE.md](../dictation/CLAUDE.md) "How to extend"); app-wide reaction → a collector in `VoiceApp.onCreate`; per session → read `app.settings.value` at start.
- **Bubble look control:** a setting as above, plus a `SliderRow` in `BubbleLookEditor` (local state, save on finish). Update `BubblePreview` and the bubble side ([../dictation/](../dictation/CLAUDE.md) `BubbleController`/`GlassStyle`) together.
- **Preset tint:** add to `BubblePalette.SWATCHES` ([../data/BubblePalette.kt](../data/BubblePalette.kt)). `GlassStyleTest` requires unique names, chroma ≤ 0.3, and white marks for every swatch except Frost and Sand.
- **Palette token:** add a field to `VoiceColors` with both Light and Dark values; map it in both `darkColorScheme`/`lightColorScheme` blocks if Material components should pick it up.
- **Tab:** add a `Tab` entry and `when` branch in [../MainActivity.kt](../MainActivity.kt). Start the screen with `TopBar` on a `Voice.colors.paper` background and read state from VoiceApp singletons with `collectAsStateWithLifecycle()`.
- **Onboarding step / settings shortcut:** add a function to `SystemLinks` built on `start()` (returns false on failure) with a fallback intent. Add a check to `SetupState`/`readSetup` (re-run on resume) and a `SetupStep` in `SetupCard`.
- **Model:** catalogue only ([../asr/ModelCatalog.kt](../asr/ModelCatalog.kt)); ModelsScreen renders `ModelCatalog.MODELS`/`VOICE_MODELS` automatically. See [../asr/CLAUDE.md](../asr/CLAUDE.md), [../tts/CLAUDE.md](../tts/CLAUDE.md).
